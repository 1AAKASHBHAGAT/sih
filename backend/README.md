## 🤖 AI Models — Honest Documentation

This platform uses two custom-trained PyTorch models alongside a zero-shot baseline.

### 1. Domain Classifier

| Property | Detail |
|---|---|
| **Model** | `distilbert-base-uncased` fine-tuned |
| **Task** | Multi-class domain classification (9 categories) |
| **Training data** | ~180 synthetic citizen-complaint examples (Jharkhand-context) |
| **Data note** | Training data is **synthetic** — generated for this hackathon prototype. It is NOT real government data. This is standard practice for a competition prototype. |
| **Architecture** | DistilBERT + linear classification head (fine-tuned via `transformers.Trainer`) |
| **Validation accuracy** | **97.8%** on val split (10 epochs, 360 train / 90 val, CPU, ~5 minutes) |
| **Mode flag** | `CLASSIFIER_MODE=finetuned` or `CLASSIFIER_MODE=zero-shot` |

### 2. Urgency Scorer

| Property | Detail |
|---|---|
| **Model** | 3-layer PyTorch `nn.Module` feed-forward network |
| **Task** | Regression — predict urgency score 1-10 |
| **Input features** | Keyword counts (high/med/mild severity), text length, 9-dim domain one-hot (13 total) |
| **Training data** | ~85 synthetic examples with heuristically-assigned labels |
| **Data note** | Labels are **heuristic** (generated by rule) — the point is a trained model replaces a static rule at inference time. |
| **Validation MAE** | **1.45 points** on 1-10 scale (V2 architecture, 200 epochs, 167 examples, 18 features) |
| **Mode flag** | `URGENCY_MODE=model`, `URGENCY_MODE=rules`, or `URGENCY_MODE=auto` |

### 3. Zero-Shot Baseline (comparison)

| Property | Detail |
|---|---|
| **Model** | `facebook/bart-large-mnli` via HuggingFace Inference API |
| **Claim** | PRD cited "90%+ accuracy" — this is the vendor's benchmark on NLI tasks, NOT measured on our complaint data |
| **Honest position** | Zero-shot is a **strong baseline** for a hackathon, but makes no guarantees on Jharkhand civic-complaint domain text |

### Switching Modes (Demo)

```bash
# Use fine-tuned DistilBERT (after training)
CLASSIFIER_MODE=finetuned URGENCY_MODE=model uvicorn app.main:app --reload

# Use BART zero-shot API (requires HUGGINGFACE_API_KEY)
CLASSIFIER_MODE=zero-shot uvicorn app.main:app --reload

# Compare both live — change env var, restart, submit same complaint
```

## 🗄️ Database Architecture & Supabase Migration

The backend uses **SQLAlchemy 2.0** with **Alembic** schema migrations, supporting production **Supabase PostgreSQL** with a seamless local **SQLite** fallback for offline development.

### 1. Supabase PostgreSQL Setup
To connect to a live Supabase PostgreSQL database:
1. Create a project at [https://supabase.com](https://supabase.com).
2. Obtain your PostgreSQL Connection URI from Project Settings ➔ Database.
3. Create a `.env` file in `backend/` and set:
   ```env
   DATABASE_URL=postgresql://postgres.xxxx:your_password@aws-0-ap-south-1.pooler.supabase.com:6543/postgres
   USE_SQLITE=false
   ```

### 2. Local SQLite Fallback
If `DATABASE_URL` is omitted or `USE_SQLITE=true` is set, falls back to local SQLite:
```env
USE_SQLITE=true
```
